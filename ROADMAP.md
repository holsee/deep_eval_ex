# DeepEvalEx Roadmap

An idiomatic Elixir port of [DeepEval](https://github.com/confident-ai/deepeval)
for LLM evaluation, compatible with deepeval's test case and test run formats.

Parity is measured against **deepeval 4.3.1**: names, scoring, defaults and the
`test_run_<timestamp>.json` export follow it unless a section below says
otherwise.

---

## Shipped

### Metrics

| Metric | deepeval equivalent | Notes |
|--------|---------------------|-------|
| **ExactMatch** | `ExactMatchMetric` | No LLM call |
| **GEval** | `GEval` | Criteria or evaluation steps, rubrics |
| **Faithfulness** | `FaithfulnessMetric` | Claims vs. truths, yes/no/idk verdicts |
| **Hallucination** | `HallucinationMetric` | Lower is better |
| **AnswerRelevancy** | `AnswerRelevancyMetric` | |
| **ContextualPrecision** | `ContextualPrecisionMetric` | Weighted cumulative precision |
| **ContextualRecall** | `ContextualRecallMetric` | |
| **ToolCorrectness** | `ToolCorrectnessMetric` | Deterministic, optional LLM tool-selection score |

Metric names match deepeval's `__name__`, so exported runs line up with
deepeval's.

### Evaluation engine

- [x] Concurrent test cases (`Task.async_stream`) and concurrent metrics
      within a test case (`:metric_concurrency`)
- [x] Per-metric config overrides run-level options
- [x] Timeouts per metric and per test case; a timed-out or raising metric
      becomes an **errored** result (`error` set, no score) instead of
      crashing the run or failing silently
- [x] Errored results are recorded separately from failures, as deepeval does
- [x] Token usage, cost and evaluation model captured on every result
      (`DeepEvalEx.LLM.Usage`, `DeepEvalEx.LLM.Pricing`, `:model_pricing`)
- [x] Judge temperature defaults to `0.0`, like deepeval
- [x] Telemetry events (`[:deep_eval_ex, :metric, :start | :stop | :exception]`)
- [x] ExUnit assertions (`assert_passes`, `assert_fails`, `assert_score`,
      `assert_evaluation`)

### Test cases and test runs

- [x] `DeepEvalEx.TestCase` carries deepeval's `LLMTestCase` fields
      (`name`, `tags`, `metadata`, `comments`, `token_cost`,
      `completion_time`, `tools_called`, `expected_tools`, ...)
- [x] `DeepEvalEx.evaluate_run/3` writes deepeval-compatible
      `test_run_<timestamp>.json` files (`:results_folder` /
      `DEEPEVAL_RESULTS_FOLDER`, `:identifier`, `:hyperparameters`)
- [x] `DeepEvalEx.TestRun.load/1` reads runs written by deepeval or
      DeepEvalEx
- [x] Byte-for-byte parity with golden fixtures generated by deepeval 4.3.1
      (`test/fixtures/deepeval`, `scripts/parity/generate_fixtures.py`)

### LLM adapters

- [x] OpenAI: structured outputs, `max_completion_tokens`, reasoning models,
      `base_url` for OpenAI-compatible gateways
- [x] Anthropic: Messages API
- [x] Ollama: local models via `/api/chat`
- [x] Mock: canned responses for tests

### Tooling

- [x] Devcontainer matching the CI toolchain, with deepeval 4.3.1 installed
      for observing reference behaviour and regenerating parity fixtures
- [x] CI gate: format, `--warnings-as-errors` compile, `credo --strict`,
      tests, Dialyzer
- [x] Schema validation with Peri (Ecto removed, see ADR-0008)

## Planned

Groups are roughly in priority order. Each item aims for deepeval 4.3.1 parity
where deepeval has the feature.

### Agent evaluation

- [ ] Trace and span model for agent runs (LLM, tool, retriever and agent
      spans), attachable to test cases and exported like deepeval's traces
- [ ] Trajectory matching with match modes (exact, in-order, any-order,
      subset / superset)
- [ ] `TaskCompletion`, `StepEfficiency`, `PlanQuality`, `PlanAdherence` and
      `ArgumentCorrectness` metrics
- [ ] Environment-state grading: score the end state an agent leaves behind,
      not only its transcript

### Trials and statistics

- [ ] Repeated trials (epochs) per test case with reducers: mean, majority,
      `pass@k`, `pass^k`
- [ ] Confidence intervals on scores and pass rates
- [ ] Paired comparison of two runs over the same test cases
- [ ] `mix deep_eval.compare` to diff saved test runs

### Judge quality

- [ ] `DAGMetric`: deterministic decision trees of judge steps
- [ ] Arena pairwise comparison (`ArenaGEval`)
- [ ] Judge alignment API: measure a judge against human labels

### Multi-turn

- [ ] `ConversationalTestCase` with turns, and its test run export
- [ ] Conversational metrics (knowledge retention, role adherence,
      conversation completeness, turn relevancy, conversational GEval)
- [ ] Conversation simulator

### Later

- [ ] Safety metrics (bias, toxicity, PII leakage, ...)
- [ ] Online evaluation of production traffic
- [ ] Phoenix LiveView components for live results (see the
      [Phoenix Integration](wiki/guides/Phoenix-Integration.md) design notes)

### Out of scope for now

- Benchmarks (MMLU, GSM8K, ...)
- Red teaming
- Confident AI cloud sync

## Architecture

```
lib/deep_eval_ex/
├── evaluator.ex             # Concurrent evaluation engine
├── ex_unit.ex               # ExUnit assertions
├── telemetry.ex             # Telemetry events
├── test_run.ex              # deepeval TestRun export/import
├── test_run/                # JSON encoding, local results folder
├── llm/
│   ├── adapter.ex           # Behaviour for LLM providers
│   ├── usage.ex             # Token usage capture
│   ├── pricing.ex           # Per-model cost
│   └── adapters/            # openai, anthropic, ollama, mock
├── metrics/                 # BaseMetric + one module per metric
├── prompts/                 # Judge prompt templates (from deepeval)
└── schemas/                 # TestCase, ToolCall, Result, metric outputs (Peri)
```
